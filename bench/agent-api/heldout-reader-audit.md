# 独立读者任务验收

本轮提前冻结 6 个真实读者问题及请求、字节预算，题目未交给实现者，也未修改 tinybench 标准答案。验收只调用注入本地 `dist` 内容的 handler，单话题正文实际经过 reader 读取。没有网络、生产请求或真实数据库写入。完整请求与返回正文见同目录 `heldout-reader-audit.json`。

6 个任务均取得足以回答的来源，且在原定预算内。查询拆解和证据选择由审查者执行；这不是受控的 agent 完整回答实验，不能报告成真实用户成功率。请求数包括搜索、正文读取和资料关联查询；字节数为完整响应正文的 UTF-8 bytes，不计 HTTP 头、内部目录加载或压缩。

## 保留的质量问题

- 数学任务的完整自然语言问题在指定日期范围内返回 0 条。改为“编程门槛 数学”后返回 14 条，前两条覆盖所需证据，但前 5 条还有 3 个其他数学话题。接口支持人工或 agent 改写恢复，不能保证把完整自然语言问题直接当 `q` 就成功。
- 提示词优化问题返回 3 条，只有首条直接回答具体实践；另外两条谈宽泛 RSI 收益与人的位置。排行把最直接证据放在首位，但没有完全满足用户排除宽泛项目讨论的意图。
- 日报与周报可能重复描述同一事件。研究复现任务的首轮两条结果是同一经历的日、周版本，使用者需要按日期和来源归并，不能把它们算两次独立复现失败。
- 缺刊恢复可以在预算内完成，但查早期日期要读两页目录；目前恢复链接主要引导目录和最新刊，尚不是直接返回“最接近目标日的可用期数”。只能说目标日没有已发布正文，不能由此断定群里没有消息。

## 旧入口也可完成的路径

这些任务以前并非全部不可完成。以视频学习任务为例，旧入口可下载整个资料库，找到 TOFU，再跟到相关整页日报。冻结的旧公开资料库按原生成器格式为 275,814 bytes，加上 6,494 bytes 的日报，合计两次请求、282,308 bytes。本轮新接口用三次请求、6,683 bytes 取得具体正文、论文及反向关联。该对照反映返回量与定位粒度，不证明模型理解或用户完成率提高。

缺刊也能用旧 `index.md` 列表确定实际有稿日期，再读 8 月 26 日日报。当前保留相同发布目录的文件合计两次请求、26,982 bytes；新接口本轮是五次请求、14,200 bytes。这里旧 index 的体积取自当前构建，是可行路径说明，没有单独测旧版本性能。新接口为恢复提供结构化目录与版本固定分页，但请求数不一定更少。

## 来源和解释边界

所有读到的正文都保留来源网页、日期/区间和群版标识。科研复现、优化失败和建议属于群友经历或判断；数学工程外溢仍是未决讨论；引文工具是作者介绍，正文明确不保证消除幻觉。AI 评论与讨论摘要有单独标题，不能混成群友事实。

本地 public catalog 有 889 条话题/资料、41 项已发布日周刊（其中可读日报 38 期）；原始输入有无稿日期，所以不能把源文件的 52 个日期当作 52 期可读日报。测试没有阅读原始群聊、头像或私有 SQL。

验收时的 catalog revision、BM25、query、Content API、Library API 及 catalog SHA-256 均写入 JSON，便于确认验收对应版本。冻结题目的 source 和 anchors 是预设证据要求，不是运行时定向找答案的接口参数。候选选择与改写由审查者执行，因此这里只报告证据可用性和实际成本。

最终实现另用 `replay-reader.mjs` 重放相同的 23 次请求。除加载时间外，所有响应正文与状态均与原记录一致，字节与预算保持不变。最终源码哈希及逐请求对照见 [reader-replay.json](reader-replay.json)。
