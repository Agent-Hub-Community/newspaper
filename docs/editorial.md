# 读者内容规则

本文说明网站上的读者内容应满足什么条件、怎样呈现：版面和缺稿、重点、AI 锐评、原始讨论节选和隐私。
构建和入库脚本会检查其中能机器检查的部分；其余部分由编辑在审核时负责。

选题、写法、审稿和锐评怎样写，属于写稿流程，见 [bot-workflow](https://github.com/Agent-Hub-Community/bot-workflow)。本文只写读者数据和网页这一侧的规则。

## 定位

读者是 Agent Hub 各群的研究者和开发者。多数人从微信里点开日报，在手机上快速读讨论的结论，也有人在桌面回看往期。

- 每个群一版，外部资讯另占一版。首页打开就是可读的正文。
- 每版提炼话题中的认识、共识和分歧，不逐人复述发言，按讨论深度排序。条数由材料决定。
- 语气克制、清楚，有编辑判断。阅读优先于动效。
- 网站不做营销式首页、发言流水账、逐人观点卡片、虚构的排名或分数。

## 缺稿

- 某群某天没有记录，或核验后没有合格条目时，该版的 `stories` 为空数组，页面如实显示缺稿。
- 不用其他群或其他日期的内容填充，不复用旧日新闻，也不补造稿件。
- 新群在读者版面起始日期（`lib/groups.mjs` 的 `pageFrom`）之前没有版面，历史刊期不补造它的稿件或路径。

缺稿在页面上怎样显示，见 [界面规则](ui.md#日报版面)。

## 重点

每条正文的 `emphasis` 数组列出要加粗的原文片段。模型先选，编辑再逐条审核、补全或替换。最终标注属于编辑审核，不冒充模型原始输出。

程序检查的条件（[`lib/emphasis.mjs`](../lib/emphasis.mjs)）：

| 条件 | 说明 |
|---|---|
| 精确匹配 | 片段与正文逐字一致，在正文里只出现一次 |
| 不重叠 | 片段之间不重叠，单个片段不跨自然段 |
| 长度 | 每个片段至少 2 个字符，首尾没有空白；合计不超过正文的 30% |

编辑审核的条件：

- 长文按自然段审核。每个承载独立判断、机制、分歧或限制的自然段，通常选 1 处；短文选 1 到 2 处。只做背景或过渡的段落可以不标。
- 选表达完整判断的片段，保留必要的限定，不只标名词，不整段涂满。
- 不把未核实的说法作为确定事实突出。读者只扫重点，也应能抓住主要进展。

呈现：

- 网页只把精确匹配的片段转义后包进 `strong`，不解析模型给出的 HTML 或 Markdown。
- 日报和周报都用浅色底线加适度加粗，标记在换行处逐行延续。深色主题用较暗的底色。
- 原始讨论保留原话，不加重点。

## AI 锐评

每条正文后有一段 `aiComment`（周报字段名是 `review`），页面上标为“AI 锐评”，显示在正文后、赞踩前。

- 锐评是独立的 AI 编辑观点，不代表群友共识，也不是来源证据。页面上与正文分开标注。
- 结构校验要求 6 到 90 个字符、单行、不含 `<` 和 `>`。通过校验不代表锐评可靠。
- 锐评按正文版本 ID 合并。缺条、重复，或正文改过以后的旧锐评都会报错。
- 新入库的日报刊期，每条都要有锐评。空白日期不补锐评。
- 赞踩针对整条内容。新增锐评不重置已有票数。

## 原始讨论节选

有 `discussion` 字段的话题，在正文下显示“原始讨论 N 条 · M 人”按钮，点开后显示节选。编辑核对原始消息后，才附加这个字段。

- 节选只含匿名编号（页面显示为“群友 N”）、时间、原话和可选的引文。编号只在一个话题内对应同一位发言者，不跨话题关联身份。
- 姓名、微信 ID、消息 ID 和身份映射不进入读者数据。
- 节选保留原话。发言者匿名，不等于内容已经脱敏：原话里出现的群友昵称也要换成“群友 N”。
- 图片在节选里显示为 `[图片]`，不放模型写的图片描述。校验拒绝以 `[图片（` 开头的文字。
- 外部资讯不附节选。给 agent 用的 Markdown 和查询接口不含节选原话。

字段格式见 [数据格式](data-format.md#原始讨论节选)。

## 隐私

读者内容包括标题、副题、正文、重点、AI 锐评、资料标签、原始讨论节选、公开榜单和资料库。这些内容遵守以下规则：

- 不出现人名、微信昵称、账号和联系方式。正文用“群友”“分享者”等代称。
- 不写个人背景（所在地区、学校、身份、工作经历），不写群友所在的公司或透露的内部业务。
- 可以保留公开的项目名、论文和代码链接，但不把公开作者重新关联到群内身份。
- 不含群 ID、消息 ID、微信 ID、附件密钥和常见令牌。入库脚本和测试检查这些模式。
- 原始聊天、身份映射、完整统计、模型原稿和审核证据只留在维护者本机，不进仓库。

活跃榜：

- 只公开前三名的名次、头像和覆盖范围。分数、消息数和计分规则不进仓库，构建时也删掉计分明细。
- 榜单统计参与次数，不是内容质量分。

头像：

- 活跃榜、周榜和资料库的头像仍能认出人，所以头像不算匿名化。
- 头像逐张审核后才进入仓库。微信返回的“暂时无法查看”占位图和未成年人照片要排除。这种占位图不能说明成员已退群。
- 确认不了的头像不发布，页面显示默认头像，名次或分享记录保留。
- 资料库头像只出现在网页上。资料库的 JSON 和 Markdown 只有分享日期和群。

机会（招聘、活动、征稿）不写发帖人，不含个人联系方式，校验会拒绝邮箱、手机号和微信号。

删除个人内容的请求方式见 [CONTENT-NOTICE.md](../CONTENT-NOTICE.md)。
