# 搜索与词表

这篇文档说明站内搜索（`/search/`）和公开检索接口（`/content/search`、`/library/search`）怎么打分排序、怎么把群里常说的缩写和黑话扩展成正式名称，以及平时怎么维护词表。Worker 接口的参数和返回格式见 [`feedback/README.md`](../feedback/README.md)。

## 搜哪些内容

`/search/` 在浏览器本地搜索四类内容：

- 日报和周报的具体话题（标题、正文、AI 锐评、资料卡片名称）；
- 外部资讯底部的“动向观察”；
- 资料库条目；
- 招聘、活动与征稿机会。

搜索索引 `search/data.js` 由 [`lib/search-render.mjs`](../lib/search-render.mjs) 在构建时生成，只有读者点开搜索页时才会下载。里面不包含原始讨论节选的聊天原话。读者在网页搜索框里输入的词直接在浏览器本地计算，不会上传给服务器（如果开启了统计，详见 `feedback/README.md` 的脱敏说明）。

## BM25 词面打分规则

网页端和 Worker 接口共用 [`site/bm25.js`](../site/bm25.js)：

- 中文按相邻两字（bigram）切分，英文和数字按整词切分；标题、关键词、正文的权重比是 `3 : 2 : 1`。
- 查询词不用加空格。一条内容要想排出来，命中的词按稀有度（IDF）加权后至少要占整条查询权重的 `1/4`，而且总得分不能低于第一名的 `30%`——这样搜“长上下文模型”时，只沾了一个“模型”的无关文章就不会混进来。
- 如果读者勾选了栏目、群或时间范围，先过滤范围再算“第一名的 `30%`”门槛，避免范围外的高分结果把范围内的有效匹配压没了。
- 中英文日常提问词（“怎么”“如何”“群里有没有人聊过”、`what`、`does`、`the` 等）自动忽略，不占查询权重。

## 黑话与同义词扩展

群里平时说话爱用缩写和外号（比如把 Anthropic 叫“A社”、把 Google Gemini 叫“哈基米”、把基座模型叫“基模”）。构建时 [`lib/synonyms.mjs`](../lib/synonyms.mjs) 会把三处词表合成一张查询扩展表：

| 来源 | 数据文件 | 扩展方向 | 权重折扣 |
|---|---|---|---|
| 资料库关键词别名 + 黑话词典里的全部词条 | `data/library-keywords.json`、`data/glossary.json` | 单向：搜别名／外号时，同时去搜对应的规范关键词或正式名称 | `1.0`（原分） |
| 黑话词典里的“缩写”“行话”“网络用语” | `data/glossary.json` | 双向：缩写与正式名称互相都能搜到 | `0.85` |
| 日常同义词（如“画图／绘图／作图”） | `data/search-synonyms.json` | 双向互搜 | `0.85` |

举两个例子：

- 搜“A社”会把 `Anthropic` 的文章找出来（单向）；但反过来搜 `Anthropic` 时，不会去把只写了字面“人类学”的内容拉出来，因为“代号”和“梗”只走单向。
- 搜“基座模型”能把只写了“基模”或“底模”的讨论也找出来，排在原词命中的后面（`0.85` 折扣）。

### 防误召回的几条卡口

为了防止同义词一扩就把不相干的内容全捞出来，`bm25.js` 额外卡了四条规则：

1. 扩出来的多词英文名，必须命中里面最罕见的那个词才算数。比如搜“哈基米”扩出 `Google Gemini`，文章里得有 `Gemini` 才算命中，光提 `Google` 不算。
2. 查询里没被同义词替换掉的其余词，自己也得单独凑够 `1/4` 的权重覆盖。这样搜“Agent 记忆”扩成“智能体 记忆”后，光提“智能体”、不提“记忆”的文章进不来。
3. 站内从没出现过的英文词或带数字的词（比如 `dpsk4.1`）照样计入查询总权重，不会因为只剩一个 `1` 能匹配就吐出一堆无关文章。如果去掉未出现的普通英文词后、剩余词还占一半以上权重，搜索会自动降级重试一次，并在接口返回的 `dropped_terms` 里标出来。
4. 像 `GPT-7`、`DeepSeek V5` 这种“已知家族名 + 站内从未出现过的版本号”，即使模型名和数字分开出现过，合在一起没出现过就直接返回 0 条，并在接口的 `missing_versions` 和 `known_versions` 里告诉调用方站内实际有哪些版本。

## 平时怎么维护词表

- 缩写、外号、梗和圈内行话统一放进 `data/glossary.json`；日常同义词放进 `data/search-synonyms.json`。两边不准出现重复写法，重了构建会直接报错。
- 往 `data/search-synonyms.json` 加词时，只放意思相同、能直接互换的词，别把上下位词或有歧义的词塞进去（比如“代理”在群里多半指网络代理，不能和 `Agent` 绑成双向同义词）。
- 如果黑话词条对应资料库里的某个规范关键词，在词条里填上 `keyword` 字段，它的写法就会自动并入该关键词的别名表。

## 语义检索（Worker API）

除了上面的 BM25 词面搜索，Worker 的 `/content/search` 接口还会用 Cloudflare Workers AI 的 `@cf/qwen/qwen3-embedding-0.6b` 模型算查询向量，跟 `data/semantic-vectors.json` 里的文档向量算余弦相似度（取 `≥ 0.5` 的前 50 条），再用 RRF（Reciprocal Rank Fusion）和 BM25 前 50 条融合排序。每条返回结果会标明 `matched_by: "words" | "meaning" | "both"`。
