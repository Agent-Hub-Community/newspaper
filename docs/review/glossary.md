# AgentHub 群聊黑话审核规范

群聊黑话词典收录 AgentHub 群里常用、新读者或 agent 读日报时可能看不懂的说法：缩写、代号、梗和行话。
词典公开发布在 `/glossary/`，也是全站搜索和资料库搜索的词表（规则见 [搜索与词表](../search.md)）。审核 agent 按这份规范通读
聊天分块，编辑合并后写进 `data/glossary.json`。聊天分块由 [bot-workflow](https://github.com/Agent-Hub-Community/bot-workflow)（即将开放）导出，只放在被 Git 忽略的 `scratch/` 下。

## 输入

`scratch/glossary/chunk-NN.txt` 每行一条消息：`日期 群 时间 化名: 正文`。化名只在当天有效，不对应具体成员。
链接、图片、引用块和 @ 提及已经去掉。这些是私有聊天记录，只用来判断词义，不能写进输出的释义。

## 收录

- 缩写：如 oai、cc、ds、ddl。
- 代号：群里对模型、公司、产品的非正式叫法，如用一个字或外号指代某个模型。
- 梗：群里反复用来指代某件事或某种测试的说法，如用某个固定的提示词测试模型。
- 行话：研究和工程里的术语，群里用法有特定含义、新人不一定懂的，如 harness、RSI、OPD。
- 网络用语：只在它在群里有特定含义时收录。

判断标准：一位刚进群的 Agent 研究者读日报或聊天时，会不会因为不认识这个说法而读不懂？会就收录。
AI、LLM、GPU 这类人人都懂的词不收，除非群里有特殊用法。

## 不收录

- 指向任何具体群友或私人的外号、昵称、梗、玩笑，以及人名、单位和身份信息。词典里的每一条都只能解释概念或产品，不能让人联想到某位成员。
- 针对人或群体的侮辱性、歧视性用语。公司、模型和产品的别称一律收录，包括戏谑和谐音写法，如 Anthropic 的“a÷”“a畜”。
- 只出现一两次、含义靠猜的说法。

## 核实

- 释义只写聊天上下文能支持的含义。上下文不够、需要凭常识推断时，`confidence` 写 `low` 并在 `note` 说明。
- 代号和缩写要写出指代的正式名称（`refersTo`），例如官方模型名、公司名。
- 不做网页搜索；需要确认正式名称时可以打开官方页面。

## 输出

每个审核 agent 写到 `scratch/glossary/found-NN.json`（NN 与分块编号相同），格式是数组：

```json
[
  {
    "term": "oai",
    "variants": ["OAI", "oa"],
    "meaning": "OpenAI 的缩写。",
    "category": "缩写",
    "refersTo": "OpenAI",
    "count": 12,
    "evidence": ["2026-09-29 三群 01:24"],
    "confidence": "high",
    "note": ""
  }
]
```

- `term`：群里最常见的写法。`variants`：其他写法，不含 `term` 本身。
- `meaning`：中文一句话，不超过 40 个汉字，平实具体，不写聊天里的评价。
- `category`：`缩写`、`代号`、`梗`、`行话`、`网络用语` 之一。
- `count`：本分块里大致出现的次数。`evidence`：一到两条消息的“日期 群 时间”，只用于编辑核对，不发布。

## 编辑合并

1. 合并各分块的同一词条，`count` 相加，`variants` 取并集，释义选最准确的一条。
2. 删去 `confidence` 为 `low` 且无法从证据确认的条目。
3. 检查每一条都不指向具体群友。
4. 代号或缩写对应资料库已有的规范关键词时，在 `keyword` 字段写上该关键词，搜索时 `term` 和 `variants` 会作为它的别名。
   分类也影响搜索：缩写、行话、网络用语的各写法和正式名称双向互通，代号和梗只从写法指向正式名称。
   新写法已在 `data/search-synonyms.json` 里时，从同义词表删掉再写进词条；两边重复时构建会报错。
5. 写进 `data/glossary.json`，运行 `npm test` 和 `npm run build`。字段约束见 [数据格式](../data-format.md#黑话)。
